- 처리: 선택

## Errors

- 401 UNAUTHORIZED: 토큰 없음·만료·유효하지 않음
- 403 FORBIDDEN: 본인에게 배정된 버디 항목이 아님
- 404 NOT_FOUND: `booking_item_id` 없음
- 422 VALIDATION: `booking_item_id` 누락

## 비고

- 권한: buddy 본인에게 배정된 항목만.
- AI 엔드포인트: 사실 필드(가격·운영시간·좌표·가능 날짜)는 DB 값, LLM은 선택·순서·설명만 생성. 응답은 JSON.
- 해커톤 범위 외, 명세만 유지.

## v3.8 추천 동선 (route)
(위 예시의 route는 앞 세 곳만 줄여 보인 것. 심우장 구간의 `source: "route"`·`path`는 경로를 받아 둔 경우의 모양 예시)
- 첫 문장 = 여행자 요청 요약(식단·기타·알레르기·기타 알레르기·속도). 이제 `request.diet_other`·`allergy_other`('기타' 직접 입력)도 들어간다: "비건, 기타: 고수, 버섯 알레르기, 복숭아 알레르기 요청이 있어요. 식당에서 꼭 확인해 주세요." LLM을 쓸 때도 같은 요약을 자료로 넘긴다.
- 동선 = 버디 항목 코스(`course_id`)의 장소(그날 여는 곳) + 여행자가 버디 요청에서 고른 **'더 가 보고 싶은 곳'**(`request.places`, 그날 여는 곳, 코스에 없는 곳, 최대 3곳). 코스도 요청 장소도 없으면 `places`(버디 관심사로 고른 곳)로 만든다.
- 순서 = 걷는 거리가 가장 짧은 순서 (`services/courses.best_order`, 돌아오지 않는 한 줄 길). **코스가 있으면 코스 첫 장소는 그대로 처음**(만나는 곳). 8곳 이하는 모든 순서를 다 보고, 거리가 같으면 장소 id 순. 좌표 없는 장소는 맨 뒤. 순서는 코드가 정하고 LLM은 바꾸지 않는다(LLM 자료에는 'Suggested walking order (fixed by the app)'로만 들어감).
- 구간 거리 = 저장한 OpenStreetMap 실제 도보 경로(`walk_routes`) → 없으면 직선 × 1.3. 걷는 분은 4 km/h 올림, 거리는 10 m 반올림 (TR-02 `legs`와 같은 계산).
- 응답: `route[]`(`place_id, name, name_en, lat, lng, from_course, walk_m_from_prev, walk_min_from_prev, source, path` — 첫 곳은 `walk_*`·`source`·`path`가 null), `route_walk_m`, `route_walk_min`, `route_source`(`route` | `estimate` | `mixed`). `places`(장소 자료)는 예전처럼 코스 순서.
- 템플릿 안내(`brief`, LLM 없을 때)는 "추천 순서는 A → B → C (걷는 약 N분)"으로 같은 순서를 쓴다.
- 화면(B02·B03 요청 카드): 'AI 동행 준비 자료' 아래 '추천 동선' — "1. 장소" 줄 사이 "도보 N분 · Nm", 고른 곳 표시, 실제 경로면 '경로 © OpenStreetMap'.
