# AI 역사 스토리 (RAG)

- 번호: AI-02
- Method / Path: `POST /ai/story`
- 역할: 전체
- 화면: T4
- 우선순위: 필수
- 처리: 구현

## Headers

| 헤더명 | 필수 | 설명 |
|---|---|---|
| Authorization | 필수 | `Bearer <JWT>` |
| Content-Type | 필수 | `application/json` |
| Accept-Language | 선택 | `ko` 또는 `en`. 응답·에러 메시지 언어 |

## Request

Path/Query params: 없음

Body
```json
{ "place_id": 103, "question": "Why does this house face north?", "language": "en" }
```

## Response

200 OK
```json
{ "answer": "He refused to face the Japanese Government-General building to the south…", "sources": [ { "title": "성북구 문화관광 자료", "url": "..." } ], "grounded": true, "ai": false, "questions_left": 2 }
```
`question` 생략 시 장소 소개 이야기 반환. `grounded=false`면 프론트는 "자료에 없다" 안내.
`questions_left`(v3.4): 무료 이용자가 질문했을 때 오늘 남은 질문 수. 장소 소개·버디 이용자·관광객이 아닌 역할은 `null`.

## Errors

- 401 UNAUTHORIZED: 토큰 없음·만료·유효하지 않음
- 404 NOT_FOUND: `place_id`에 해당하는 장소 없음
- 429 AI_LIMIT (v3.4): 무료 이용자가 오늘 질문 3번을 다 씀. message "무료 코스에서는 AI에게 하루 3번까지 물어볼 수 있어요. 내일 다시 물어보거나, 버디와 함께 걸으면 제한 없이 물어볼 수 있어요"
- 422 VALIDATION: `place_id` 누락 또는 `language` 값 오류

## 비고

- 권한: 로그인한 모든 역할.
- AI 엔드포인트: 사실 필드(가격·운영시간·좌표·가능 날짜)는 DB 값, LLM은 선택·순서·설명만 생성. 응답은 JSON.
- RAG 문서(`places.story_doc`, `sources`. v3.3: 한국관광공사 TourAPI 개요가 있으면 시드 때 붙음) 밖의 질문이면 `grounded=false`로 응답하고 "자료에 없다"로 안내. 출처(`sources`)를 항상 포함.

## 무료 이용 질문 한도 (v3.4)

- 이용 방식은 AU-09 `GET /auth/me/plan`과 같은 규칙: 결제했고 취소되지 않은 예약에 살아 있는 버디 항목(requested·approved·confirmed)이 있으면 `buddy`, 아니면 `free`. 관광객이 아닌 역할은 제한 없음.
- `free`는 `question`이 있는 요청만 하루 3번(`rules.FREE_AI_QUESTIONS`). 장소 소개(질문 없음)는 세지 않는다. 장소가 없거나(404) 이야기 자료가 없는 장소는 세지 않는다.
- 하루 = 설정의 `today()` (`DEMO_TODAY`가 있으면 그 날). 횟수는 `ai_usage`(user_id, day, questions) 표에 남아 서버를 다시 켜도 이어진다. 한 SQL 문(`INSERT … ON CONFLICT … WHERE questions < 3`)으로 세서 동시에 눌러도 3번을 넘지 않는다.
- 429를 고른 이유: 결제를 요구하는 오류(402)가 아니라 "오늘 횟수를 다 씀"이고, 다음 날 저절로 풀린다.
- 광고(5초)는 화면에서만 보여 준다. 응답을 일부러 늦추지 않는다.
