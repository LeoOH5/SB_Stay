# 이메일 로그인 (데모 계정 전용)

- 번호: AU-05
- Method / Path: `POST /auth/login`
- 역할: 전체
- 화면: T0
- 우선순위: 필수
- 처리: 구현

## Headers

| 헤더명 | 필수 | 설명 |
|---|---|---|
| Content-Type | 필수 | `application/json` |
| Accept-Language | 선택 | `ko` 또는 `en`. 에러 메시지 언어 |

## Request

Path/Query params: 없음

Body
```json
{ "email": "emma@example.com", "password": "demo1234" }
```

## Response

200 OK
```json
{ "access_token": "jwt", "needs_role_setup": false, "user": { "id": 1, "email": "emma@example.com", "name": "Emma Clark", "avatar_url": null, "role": "tourist", "university_id": null, "language": "en", "calendar_connected": false } }
```
`role`: `tourist` | `buddy` | `guide` | `univ_admin` | `operator`

## Errors

- 401 UNAUTHORIZED: 이메일 또는 비밀번호 불일치, 또는 `password_hash`가 없는(구글 전용) 계정
- 422 VALIDATION: email/password 누락 또는 형식 오류

## 비고

- **데모 계정 전용 폴백.** 기본 로그인은 구글(AU-01)이고, 이 엔드포인트는 `password_hash`가 있는 시드 계정(tourist/buddy/guide/univ_admin/operator)만 통과한다. 구글로 만든 계정은 `password_hash`가 null이라 401.
- 인증 불필요. 응답의 `access_token`을 이후 요청의 `Authorization: Bearer <JWT>`에 사용. 응답 형식은 AU-01과 같고 `needs_role_setup`은 항상 `false`.
- 구글 콘솔 테스트 사용자 등록이 안 됐거나 OAuth 장애 시 데모를 이어가기 위한 안전장치. 화면에는 "데모 계정으로 로그인" 링크로만 노출.
