# 구글 캘린더 연동

- 번호: AU-07
- Method / Path: `POST /auth/google/calendar`
- 역할: buddy, guide
- 화면: B3
- 우선순위: 권장
- 처리: 구현

## Headers

| 헤더명 | 필수 | 설명 |
|---|---|---|
| Authorization | 필수 | `Bearer <JWT>`. buddy 또는 guide 역할 |
| Content-Type | 필수 | `application/json` |
| Accept-Language | 선택 | `ko` 또는 `en`. 에러 메시지 언어 |

## Request

Path/Query params: 없음

Body
```json
{ "code": "4/0AX4XfWh...", "redirect_uri": "https://sbstay.app/auth/calendar/callback" }
```

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| code | string | 필수 | 증분 인증(`include_granted_scopes=true`, `access_type=offline`, `prompt=consent`)으로 `https://www.googleapis.com/auth/calendar.events` 범위에 동의한 authorization code |
| redirect_uri | string | 선택 | code 발급에 쓴 redirect URI. 생략 시 `GOOGLE_REDIRECT_URI` |

## Response

200 OK
```json
{ "calendar_connected": true, "google_email": "jiwoo@gmail.com", "scopes": ["https://www.googleapis.com/auth/calendar.events"] }
```

## Errors

- 401 UNAUTHORIZED: 토큰 없음·만료, 또는 구글 code 교환 실패(만료·재사용)
- 403 FORBIDDEN: buddy/guide 역할이 아님, 또는 code의 구글 계정이 로그인한 `google_sub`와 다름
- 409 CONFLICT: 교환된 토큰에 `calendar.events` 범위가 없음(동의 화면에서 체크 해제) 또는 refresh token 미발급(`prompt=consent` 없이 재동의)
- 422 VALIDATION: `code` 누락

## 비고

- 로그인(AU-01)과 분리된 **증분 인증**. 처음 로그인 때는 `openid email profile`만 받고, 버디가 B3 일정 관리 화면의 "구글 캘린더 연동" 버튼을 누를 때만 캘린더 범위를 추가로 요청한다.
- 저장: refresh token은 `TOKEN_ENCRYPTION_KEY`(Fernet)로 암호화해 `users.google_refresh_token`에, `users.calendar_connected=true`. access token은 저장하지 않고 호출 때마다 refresh.
- 연동 이후 BK-04에서 buddy/guide 항목이 `confirmed`가 되면 `services/google_calendar.py`가 버디의 기본 캘린더(`primary`)에 이벤트를 만들고 `booking_items.google_event_id`를 저장한다. BK-05 취소 시 삭제. **단방향 푸시**(구글 → 우리 동기화 없음).
- 이미 연동된 상태에서 다시 호출하면 토큰을 덮어쓴다(재동의).
- 구글 콘솔은 테스트 모드라 refresh token이 7일 뒤 만료될 수 있음 → 데모 직전에 재연동.
