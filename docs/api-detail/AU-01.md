# 구글 로그인

- 번호: AU-01
- Method / Path: `POST /auth/google`
- 역할: 전체
- 화면: T0
- 우선순위: 필수
- 처리: 구현

## Headers

| 헤더명 | 필수 | 설명 |
|---|---|---|
| Content-Type | 필수 | `application/json` |
| Accept-Language | 선택 | `ko` 또는 `en`. 에러 메시지 언어 |

## Request

Path/Query params: 없음

Body (`code` 또는 `id_token` 중 하나)
```json
{ "code": "4/0AX4XfWh...", "redirect_uri": "https://sbstay.app/auth/callback" }
```

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| code | string | 택1 | 프론트가 구글 OAuth(Authorization Code)로 받은 authorization code. 백엔드가 `GOOGLE_CLIENT_SECRET`으로 토큰 교환 |
| redirect_uri | string | 선택 | code 발급에 쓴 redirect URI. 생략 시 `GOOGLE_REDIRECT_URI` |
| id_token | string | 택1 | Google Identity(One Tap 등)로 받은 id_token. 서명·`aud` 검증 후 프로필 사용 |

## Response

200 OK
```json
{ "access_token": "jwt", "needs_role_setup": true, "user": { "id": 1, "email": "emma@gmail.com", "name": "Emma Clark", "avatar_url": "https://lh3.googleusercontent.com/a/...", "role": "tourist", "university_id": null, "language": "en", "calendar_connected": false } }
```
`role`: `tourist` | `buddy` | `guide` | `univ_admin` | `operator`

`needs_role_setup`: 이 요청으로 users 행이 새로 만들어졌으면(처음 로그인) `true` → 프론트는 T0 역할 선택 단계로 보내고 AU-06 호출. 기존 사용자면 `false`.

## Errors

- 401 UNAUTHORIZED: 구글 토큰 교환 실패, id_token 서명·`aud` 불일치, 만료
- 422 VALIDATION: `code`와 `id_token` 둘 다 없음 또는 형식 오류

## 비고

- 인증 불필요. 응답의 `access_token`을 이후 요청의 `Authorization: Bearer <JWT>`에 사용. JWT 발급은 이메일 로그인(AU-05)과 동일.
- 처리 순서: 구글 토큰 교환(또는 id_token 검증) → userinfo(`sub`, `email`, `name`, `picture`) 조회 → users upsert → JWT.
- upsert 규칙: `google_sub` 일치 행이 있으면 `name`·`avatar_url` 갱신. 없고 `email` 일치 행(시드 데모 계정)이 있으면 그 행에 `google_sub`를 연결. 둘 다 없으면 `role=tourist`, `language`는 `Accept-Language`(기본 `ko`)로 새 행 생성하고 `needs_role_setup=true`.
- 로그인 범위는 `openid email profile`만. 캘린더 범위(`calendar.events`)는 버디가 B3에서 연동 버튼을 누를 때 AU-07로 증분 요청.
- 구글 콘솔은 테스트 모드. 데모 계정(Emma·Yuki·지우·해설사·대학 담당자·운영자)의 구글 주소를 테스트 사용자로 등록해 둔다.
