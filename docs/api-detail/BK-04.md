# 예약 항목 승인·거절

- 번호: BK-04
- Method / Path: `PATCH /bookings/{id}/items/{itemId}`
- 역할: univ_admin(dorm), buddy(buddy), guide(tour), operator
- 화면: A1, B1
- 우선순위: 필수
- 처리: 구현

## Headers

| 헤더명 | 필수 | 설명 |
|---|---|---|
| Authorization | 필수 | `Bearer <JWT>` |
| Content-Type | 필수 | `application/json` |
| Accept-Language | 선택 | `ko` 또는 `en`. 응답·에러 메시지 언어 |

## Request

Path params

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| id | integer | 필수 | 예약 ID |
| itemId | integer | 필수 | 예약 항목 ID |

Body
```json
{ "action": "reject", "reason": "해당 기간 만실" }
```

`action`: `approve` | `reject`. `reason`은 선택(거절 시 권장).

## Response

200 OK
```json
{ "id": 1, "booking_id": 501, "type": "dorm", "status": "rejected", "reject_reason": "해당 기간 만실", "decided_at": "2027-01-10T09:30:00Z", "booking_status": "partially_approved" }
```

## Errors

- 401 UNAUTHORIZED: 토큰 없음·만료·유효하지 않음
- 403 FORBIDDEN: 항목 type에 맞는 공급자가 아니거나 다른 대학·다른 사용자의 항목
- 404 NOT_FOUND: 예약 또는 항목 없음
- 409 CONFLICT: 이미 결정된 항목
- 422 VALIDATION: `action` 누락 또는 값 오류

## 비고

- 권한: 항목 type별 공급자 — `univ_admin`(dorm, 같은 `university_id`), `buddy`(buddy, 본인), `guide`(tour, 본인), `operator` 전체.
- 승인 시 `approved`, 거절 시 `rejected`(`reject_reason`, `decided_by`, `decided_at` 기록). 모든 항목이 `approved`/`confirmed`면 booking `confirmed`, 하나라도 `rejected`면 해당 항목만 제외.
- 관광객 알림은 상태값으로만 제공(발송은 MVP 제외).
- 구글 캘린더 푸시: buddy/guide 항목이 confirmed로 바뀌고 calendar_connected면 services/google_calendar.py가 이벤트 생성, booking_items.google_event_id 저장. 실패해도 승인은 성공(비동기·로그만).
