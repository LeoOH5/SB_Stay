# 화면 연결도 (2026-11-07, v3.5)

실제 앱(`frontend/src/app`)의 링크·버튼을 코드에서 그대로 읽어 정리했다(`href`, `router.push`, `LinkButton`, ‹ 뒤로, 탭바, 관리자 메뉴).
화면 번호(T·B·A)는 `docs/v3/screens`의 그림 이름과 같다. 번호가 없는 화면은 그림이 없는 화면이다.

그림 (주황 굵은 선 = 주 경로):
- 여행자 ① 둘러보기 → 장바구니: `screen-flow-tourist.png`
- 여행자 ② 장바구니 → 결제 → 내 여행: `screen-flow-tourist-trips.png`
- 여행자 ③ 로그인·가입·마이페이지: `screen-flow-tourist-account.png`
- 버디: `screen-flow-buddy.png`
- 관리자: `screen-flow-admin.png`

공통으로 늘 있는 이동은 표에서 뺐다.
- 여행자 탭바: 홈 `/home` · 숙박 `/stay` · 코스 `/tours` · 내 여행 `/trips`. 로그인·가입·장바구니·여행자 정보·결제·일정 만들기와 상세 화면(`/stay/:id`, `/tours/:id`, `/buddies/:id…`, `/trips/:id/…`)에서는 숨김.
- 버디 탭바: 홈 `/buddy` · 요청함 `/buddy/requests` · 일정 `/buddy/schedule` · 내 활동 `/buddy/activity`. 버디 로그인·지원·식비 청구·활동 기록에서는 숨김.
- 관리자 왼쪽 메뉴: 대시보드 · 대학·객실 · 예약 · 회원·버디 승인* · 산책 코스* · 식비 청구* · 신고* · 정산 (*운영자만 보임).
- 위쪽 ‹ 뒤로는 표의 "‹" 줄로 적었다.
- v3.9 여행자 위쪽 장바구니 아이콘(담은 개수 뱃지): 장바구니에 1개 이상 있을 때만 홈 · 숙박 목록 · 코스 목록 · 버디 목록 · 내 여행 · 마이페이지 위 오른쪽에 보이고, 누르면 T13 장바구니 `/cart`.
- v3.9 로그인으로 보내는 곳은 모두 `/login?next=<지금 주소>`. 로그인 · Google · 가입 · 역할 선택 뒤 `next`가 같은 사이트 경로이고 역할 영역에 맞으면(여행자는 `/admin`·`/buddy` 밖, 버디는 `/buddy`, 관리자는 `/admin`) 그곳으로, 아니면 역할별 첫 화면.

## 막힌 곳 · 끊긴 링크

없는 주소로 가는 링크는 **없다**(코드의 모든 이동 대상이 실제 페이지와 맞음). 그 밖에 눈에 띈 것(1~4는 v3.9에서 고침, 5~6은 그대로):

1. (고침) **장바구니로 가는 상시 입구가 없다.** → 담은 게 있으면 탭 화면 위 오른쪽에 장바구니 아이콘과 개수 뱃지가 보이고, 누르면 `/cart`로 간다.
2. (고침) **여행자 앱에서 버디 앱으로 가는 길이 좁다.** → 시작 화면 아래 작은 링크와 마이페이지의 '버디로 활동하기' 줄이 `/buddy/login`으로 간다.
3. (고침) **버디 지원 심사 중 '홈으로'가 여행자 시작 화면(`/`)으로 간다.** → 버튼을 '버디 로그인으로'로 바꾸고 `/buddy/login`으로 보낸다.
4. (고침) **로그인 뒤 보던 화면으로 돌아오지 않는다.** → 로그인으로 보낼 때 `?next=<지금 주소>`를 붙이고, 로그인·Google·가입·역할 선택이 안전한 같은 역할 영역 경로일 때만 그 화면으로 돌려보낸다.
5. **그림 번호가 없는 화면:** 결제 `/pay` · `/pay/success` · `/pay/fail`, 버디 내 프로필 `/buddy/me`. `/pay/success`·`/pay/fail`은 토스 결제창이 돌려보내는 주소라 앱 안 링크가 없는 게 정상이고, `/login/role`(T03)도 로그인·가입 결과로만 열린다.
