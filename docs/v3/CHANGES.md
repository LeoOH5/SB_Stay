# v3 변경 정리 — 해설사 없이 버디만, 새 디자인

브랜치 `feat/v3-buddy-only` (develop 2cfb459 기준). 기준 문서는 같은 폴더의 `CONTRACT.md`, 목표 화면은 `screens/*.png`.

## 한 줄 요약
해설사와 유료 투어를 없애고 **숙박 + 같은 학교 버디**만 예약한다. 투어는 **무료 AI 산책 코스**가 되었고,
버디 쪽에 요청 사항·성향·식사비·앨범·활동 기록·후기·신고·지원 5단계·정산을 넣었다. 화면은 쪽빛 남색 + 감 주황, IBM Plex Sans KR, 새 로고로 바꿨다.

## 왜 이렇게 바꿨나
- 외국인에게 돈을 받고 관광 안내를 하려면 관광통역안내사 자격이 필요하다. 해설사를 빼고, 역사 이야기는 확인된 자료만 쓰는 AI가 맡는다. 버디는 "해설하지 않는 친구"로 남는다.
- 서비스의 차별점은 "같은 대학 기숙사 + 그 학교 학생 버디"다. 그래서 숙박에는 버디 1명이 반드시 함께한다.

## 무엇이 바뀌었나

### 1. 예약 규칙 (B 영역 · `services/booking_state.py`)
| 규칙 | 오류 코드 |
|---|---|
| 코스는 예약 항목이 아님 | 422 `COURSE_NOT_BOOKABLE` |
| 숙박은 예약당 1개 | 422 `ONE_STAY` |
| 숙박이 있으면 버디 1명 이상 | 422 `BUDDY_REQUIRED` |
| 버디 날짜는 숙박 기간 안 | 422 `BUDDY_OUT_OF_STAY` |
- 버디 항목에 `request`(식단·알레르기·속도·가고 싶은 곳·메모), `course_id`(같이 걸을 코스), `meal_count`(0~4), `album` 추가.
- 버디 항목 가격 = 활동비 + 식사 보증금(회당 ₩20,000) + 앨범 ₩5,000.
- 수수료 = (숙박 + 활동비) × 10% + 앨범 요금 전액. 식사 보증금에는 수수료 없음.
- **개인정보 버그 수정**: 버디가 예약 상세를 보면 여행자 이름·국적·인원만, 자기 항목만 보인다(전에는 여권번호·이메일까지 보였음).
- 버디 바꾸기 `POST /bookings/{id}/items/{item}/replace-buddy`.
- 후기에 세부 점수(친절·소통·시간 약속·동네 추천)와 태그. 동행 날짜가 지나야 쓸 수 있음(409 `TRIP_NOT_DONE`).
- 앨범 `GET /bookings/{id}/album`.

### 2. 식사비 (새 기능)
여행자가 식사 횟수만큼 미리 맡긴다 → 버디가 먼저 계산하고 영수증을 올린다(`POST /buddy/meal-claims`) →
운영자가 확인한다(`/admin/meal-claims`) → 승인한 만큼 버디 정산에 더하고, 남은 보증금은 여행자에게 돌려준다.

### 3. 버디 운영 (새 기능)
- **지원 5단계** `/buddy/apply/*`: 성북구 대학 메일 인증(데모 인증번호 123456) + 만 19세 이상 → 버디 약속 7개 동의(v3.1에서 '차에 태우지 않기' 추가) → 교육 퀴즈 10문제 중 8개 → 성향 프로필 → 운영팀 승인.
  승인(AD-04)은 위 조건을 다 채워야 됨(409 `NOT_READY`).
- **신고** `POST /reports` → 같은 버디에게 2건이 쌓이면 자동 정지. 운영자가 `/admin/reports`에서 경고·정지·정지 풀기·기각.
- **성향**: 성격·같이 다니는 스타일·도와줄 수 있는 것. AI 버디 추천(AI-03)이 요청(비건 → 비건 식당 안내 가능)과 같은 학교를 점수에 반영.
- **활동 기록** `POST /buddy/activities` → 버디 프로필의 '최근 활동'과 여행자 앨범.
- **정산** `GET /buddy/settlement`: 동행별 금액, 수수료 10%, 식비 환급, 받을 날짜.

### 4. AI (A 영역)
- AI-01 일정: 숙소를 넣으면 버디는 반드시 넣고(숙박 기간 안, 같은 학교 우선), 코스는 무료로 버디 항목에 붙인다. 버디가 없으면 `warnings: ["NO_BUDDY"]`.
- AI-02 장소 이야기: 관광지 25곳(성북구청·국가유산·서울시 자료). 자료에 없으면 없다고 답함.
- AI-03 버디 추천: 성향·도움·같은 학교 가산점.
- AI-04 동행 준비 자료: 투어 대신 버디가 고른 코스·요청 사항으로.

### 5. 관리자 (B 영역)

### 1. 버디 "운전 가능" 표시 (표시만)
- `buddy_profiles.can_drive BOOLEAN NOT NULL DEFAULT false`. BuddyOut·BuddyDetailOut·`/buddy/profile`·AdminBuddyRow에 `can_drive`. 시드: 민호·준서 true.
- 화면: 버디 상세(T10)에 '운전 가능' 칩 + "차량 이동 서비스는 제공하지 않아요", 프로필 편집(지원 4단계·내 활동)에 "운전할 수 있어요 (차량 동행은 하지 않아요)", 관리자 회원표에 운전 칸.
- **왜 표시만?** 자가용으로 돈을 받고 사람을 태우는 것은 기름값·주차비 명목이라도 불법이다(여객자동차 운수사업법 제81조, 자가용 유상 운송 금지).
  그래서 앱은 운전할 수 있는지만 보여 주고, 차량 동행을 팔거나 차비를 받지 않는다.
- 버디 약속(B07)에 "여행자를 내 차에 태우지 않아요 (유상 운송 금지)" 추가 → 6개에서 **7개**. 목록은 `frontend/src/lib/codes.ts`의 `BUDDY_PROMISES` 한 곳이고, 지원 5단계 '7개 모두 확인'·관리자 '약속 7/7'이 그 개수를 쓴다(백엔드 동의는 개수를 세지 않음).

### 2. 정산 수익 구조 (AD-06 · A05)
- `/admin/settlements` 응답에 `profit {sales, sales_dorm, sales_buddy, sales_album, cost_university, cost_buddy, cost_other, profit, margin}`.
- 이익 = (숙소비 + 버디비 + 앨범) − (숙소 원가 + 버디 지급료 + 기타 원가). 원가는 대학 90%·버디 90%(지금 비율 그대로), 앨범은 원가 0, 기타 원가(카드 수수료 등)는 자리만 두고 0. 식사 보증금·승인 식비는 통과 금액이라 판매가·원가에 넣지 않는다.
- 시드 기준(2027-01): 판매가 374,000 (숙박 219,000 + 활동비 150,000 + 앨범 5,000) − 원가 332,100 (대학 197,100 + 버디 135,000 + 기타 0) = 이익 **41,900**, 이익률 11.2%.
- A05 화면 아래 '수익 구조' 표 (항목별 판매가 · 원가 · 이익 + 합계).

### 3. 시드 데이터 엑셀 검토 도구 (`backend/scripts/`)

## v3.2 버디 등급·정산율
Alembic `v3d_buddy_grade` 하나 (이전 `v3c_place_photo`). 백엔드 테스트 127개.

### 1. 등급과 정산율 (팀 결정)
| 등급 | 평균 평점 | 활동 완료 | 최소 후기 | 버디 정산율 |
|---|---|---|---|---|
| 기본 `basic` | 조건 없음 | 신규 포함 | 없음 | 70% |
| 성장 `growth` | 4.3 이상 | 5회 이상 | 3건 | 75% |
| 우수 `top` | 4.5 이상 | 15회 이상 | 5건 | 80% |
- **평가 기간**: 오늘이 든 운영 방학(없으면 가장 최근 방학) + 그 직전 방학. 방학 목록은 `app/core/rules.py` `VACATIONS` (2025 겨울 · 2026 여름 · 2027 겨울). 방학 밖 동행(예: 11월)은 세지 않는다.
- **실적**: 확정되고 날짜가 오늘 이전인 버디 항목(활동 완료) 수, 그 항목 후기의 평균·개수. 세 조건을 모두 채우는 가장 높은 등급.
- **갱신**: 매월 1일 1회. 운영자 `POST /admin/buddies/recompute-grades`(A03 '등급 다시 계산' 버튼) 또는 `uv run python scripts/recompute_grades.py [날짜]`. 크론은 아직 없다(운영 단계에서 매월 1일 위 스크립트를 돌린다). 시드 적재 끝에도 한 번 돈다(데모 '오늘' 기준).
- **정산 기준**: 숙박비를 뺀 버디 활동비에만 적용. 버디가 수락해 확정되는 순간 `booking_items.payout_rate`에 고정 → 나중에 등급이 바뀌어도 그 동행은 그대로. 버디 몫 = round(활동비 × 정산율), 나머지는 플랫폼.
  앨범은 전액 플랫폼, 식사 보증금은 통과 금액, 숙박은 대학 90% / 플랫폼 10% (그대로).
  `booking.platform_fee` = 숙박 10% + 활동비 × (1 − 정산율) + 앨범. 확정 전 항목은 버디의 지금 정산율로 어림하고, 확정 때 다시 계산.
- 고정 90%를 쓰던 곳을 모두 바꿈: `/buddy/settlement`(+`grade, payout_rate`, 항목별 `payout_rate`) · `/buddy/earnings` · `/admin/settlements` 버디 행(+`payout_rate`)·`profit.cost_buddy` · 목업.

### 2. 휴면
- 운영 기간 중 30일간 활동(완료 동행·요청 수락·가능 날짜 수정)이 없으면 `needs_recheck=true` + `dormant_since`. 방학 밖 날짜는 세지 않는다.
- 휴면 버디는 버디 목록(BD-01)·AI 추천(AI-01·03)에서 빠지고, 새 예약은 409 `BUDDY_RESTING`. 버디가 `POST /buddy/confirm-active`('계속 활동할게요')를 누르면 다시 받는다.
- 예약이 없어 생긴 휴면이라 **등급·정산율은 내리지 않는다**. 복귀 후 첫 동행은 기존 정산율로 확정되고, 그 동행이 끝난 뒤 다음 갱신에서 재산정한다.

### 3. 한국 국적 버디만
외국인 유학생은 시간제 취업 허가 문제로 유급 버디를 할 수 없다. 지원 1단계 `POST /buddy/apply/verify`에 `korean_national: true`가 필요(아니면 422 `NOT_KOREAN_NATIONAL`), `buddy_profiles.korean_national_confirmed_at` 저장.
`/buddy/apply`·AdminBuddyRow에 `korean_national`, 승인(AD-04)도 국적 확인이 없으면 409 `NOT_READY`. 화면: B06 '대한민국 국적이에요' 체크(필수), B10 확인 목록, B01 지원 자격 문구, A03 대기 표 '국적 확인' 열.

### 4. 무자격 관광 안내 방지 (그대로 유지)

### 2. 무료 이용의 제한 (정직한 제한만)
- **기본 코스만**: 순서가 정해진 5개 코스 그대로. 코스 상세에 "순서가 정해진 기본 코스예요. 내 숙소·시간에 맞춘 동선은 버디와 함께 걸을 때 짜 드려요" + '버디와 걷기'. 코스 순서·데이터는 바꾸지 않았다.
- **이야기 전 광고 5초**: '광고' 표시, 지어낸 성북 가게·모임 예시 3개(실제 가게 아님), 5초 뒤 '이야기 보기'. 이야기는 그동안 이미 불러온다(일부러 늦추지 않음). '광고 없이 보기 → 버디 신청'.
- **AI 질문 하루 3번**: AI-02 질문만 센다(장소 소개는 무제한). 4번째는 429 `AI_LIMIT`. 날짜는 `DEMO_TODAY` 기준, 횟수는 새 표 `ai_usage`에 남아 서버를 다시 켜도 이어진다. 화면은 "오늘 남은 질문 N/3", 0이면 '버디에게 바로 물어보기 → 버디 신청'.
- **실시간 도움 없음**: '도움이 필요해요' → 무료 코스엔 도와줄 사람이 없다는 안내 + 112·119·1330 + '버디와 걷기'.
- **완료 설문**: '코스 다 걸었어요' → 만족도 1~5 · 가장 불편했던 점 · 다음엔 버디와 걸어 볼래요? → `POST /tours/{id}/survey`(TR-05, 새 표 `course_surveys`) → "다음엔 버디와 함께 걸어 보세요". 할인 금액은 정하지 않아 약속하지 않는다.
- 버디 이용자는 광고·질문 제한·설문이 없다. 업셀은 모두 버디 목록이 먼저, 숙박 + 버디는 보조 링크.
- 팀이 말한 "느리게·꼬인 동선"은 넣지 않았다. 틀린 길 안내나 일부러 늦추기는 여행자 안전과 신뢰를 해쳐서, 위처럼 보이는 제한만 둔다.

## v3.6 버디 사진 기록(앨범) 정산 · 사진 실제 저장

### 1. 앨범(사진 기록) 요금도 버디 몫이 있다 (팀 결정)
- 전: 앨범 ₩5,000은 전액 플랫폼 수입. 지금: **활동비처럼 항목 정산율로 나눈다.** 버디 몫 = round((활동비 + 앨범) × 정산율), 나머지는 플랫폼. 식사 보증금은 그대로 통과 금액.
- 앨범 ₩5,000 → 버디 ₩3,500(기본 70%) · ₩3,750(성장 75%) · ₩4,000(우수 80%).
- 한 곳에서 계산: `booking_state.payout_base(it)` = 활동비 + 앨범. 예약 `platform_fee`(`recompute_totals`) · `/buddy/settlement` · `/buddy/earnings` · AD-06이 모두 이 값을 쓴다. 프론트 `codes.payoutBase` · `platformFee(숙박, [{activity, rate, album}])`, 목업도 같은 식.
- `/buddy/settlement`: `gross` = 활동비 + 앨범, 항목·합계에 `album`.

### 2. 사진을 진짜로 저장한다
- 전: 활동 사진·식비 영수증·신고 사진은 고른 **파일 이름**만 저장, 앨범은 자리 표시 타일.

## v3.7 버디 등급 매달 평가 · 버디 자격 두 경로 · 사전 교육 영상
Alembic `v3g_monthly_grade` 하나 (이전 `v3f_course_duration`). 백엔드 테스트 201개(+18, `tests/test_grades.py` 새로 씀, `tests/test_eligibility.py` 새 파일).

### 1. 등급은 매달 1일, 지난달 동행으로 (팀 결정)
| 등급 | 정산율 | 조건 (지난달 동행은 그 달만, 후기·평점은 누적) |
|---|---|---|
| 기본 `basic` | 70% | 승인 후 첫 달은 늘 기본. 그 밖에 성장 조건을 못 채우면 |
| 성장 `growth` | 75% | 지난달 동행 4회 이상 · 누적 후기 3건 이상 · 평점 4.3 이상 |
| 우수 `top` | 80% | **지금 성장(또는 우수)** + 지난달 동행 7회 이상 · 후기 5건 이상 · 평점 4.5 이상 |
- **평가**: 매달 1일, 평가 달 = 지난달(달력 기준). 12월 31일 동행은 1/1 평가에 들어가고, 1월 1일 동행은 2/1 평가에 들어간다.
- **올라갈 때는 한 단계씩**(기본 → 성장 → 우수, 기본에서 우수로 바로는 안 됨). **내려갈 때는 바로**: 우수인데 지난달 2회 → 기본, 5회 → 성장.
- 동행이 없는 달도 똑같이 평가한다 → 방학이 끝나면 대부분 기본으로 돌아간다.
- 같은 달에 '등급 다시 계산'을 여러 번 눌러도 한 번만 평가한다(`grade_evaluated_for`). 1/14에 눌러도 1/1 평가(12월 실적)다.
- 방학 두 개를 합치던 평가 기간(`VACATIONS`)은 등급에서 뺐다. `VACATIONS`는 휴면 일수(운영 기간만 셈)에만 남는다.
- **휴면은 등급을 멈추지 않는다.** 30일 휴면은 목록·AI 추천에서 빼고 새 예약을 막을(`BUDDY_RESTING`) 뿐, 등급은 매달 평가한다. '계속 활동할게요'는 휴면 표시만 지운다.
- 정산율은 그대로 예약 확정 때 항목에 고정(이미 확정된 동행은 등급이 바뀌어도 그대로).
- DB: `buddy_profiles.approved_on`(승인일, AD-04 승인 때 기록 — 있던 버디는 약속 동의일로 채움), `grade_evaluated_for`(지금 등급을 정한 평가 달).
- API: `GET /buddy/grade` 모양이 바뀌었다 — `window` 삭제, `evaluated_for, next_eval_on, stats{month, last_month_walks, this_month_walks, reviews, rating}, next, keep, first_month, note`. AdminBuddyRow `eval_*` → `eval_month, last_month_walks, total_reviews, avg_rating, evaluated_for, approved_on`. 자세한 모양은 CONTRACT §12, [BD-08](../api-detail/BD-08.md), [AD-03](../api-detail/AD-03.md).
- 화면: B05 등급 카드 = 등급·정산율 · "12월 동행으로 정함" · 12월 동행 / 누적 후기 / 평점 · "2월 1일 평가 · 우수(80%)까지" 막대(이번 달 동행·누적 후기·평점) · "등급은 매달 1일, 지난달 동행으로 다시 정해요. 올라갈 때는 한 단계씩…". A03 활동 중 표 '12월 동행 / 누적 후기 / 평점'.

### 2. 버디 자격 두 경로 + 사전 교육 (팀 결정)
- 버디 = 대학생이면서 **(a) 성북구 대학에 다니거나 (b) 성북구에 사는 사람**(어느 대학이든). 그리고 대한민국 국적, 만 19세 이상, 버디 약속 7개, 사전 교육(영상 → 퀴즈 10문제 중 8).
- 지원이 5단계 → **6단계**: ① 자격 확인 ② 약속 ③ **사전 교육 영상** ④ 퀴즈 ⑤ 프로필 ⑥ 심사.
- ① 자격 확인 두 갈래:
  - 성북구 대학 메일 인증(인증번호, 그대로).
  - 성북구 거주 확인: 다니는 대학 이름 + 주소 증빙 사진 + 재학 증명 사진(`POST /uploads`로 올린 `/media/...`) → `POST /buddy/apply/residence`. 운영자가 승인할 때 두 사진을 보고 확인한다(승인 = 서류 확인).
- ③ 교육 영상 5개: 성북구 한눈에 보기 · 길 안내와 교통 · 안전과 응급 · 역사 기본 상식(해설이 아니라 기본 상식) · 버디 약속과 하지 말 것(유료 해설·차량 동행 금지). 데모라 영상 파일은 없고 "영상 준비 중" 카드 + '다 봤어요'. 다 봐야 퀴즈가 열린다(409 `EDUCATION_NOT_DONE`).
- 퀴즈: 문제 13개(지하철역 · 응급 시 119 · 한양도성 기본 상식 3개 추가) 중 10개를 낸다. 돈·선물 거절, **버디는 역사 해설을 하지 않음**, 응급 번호 문제는 늘 들어간다. 8개 이상 통과.
- 승인 조건(AD-04, 409 `NOT_READY`): 자격 경로 하나(거주 경로는 서류 두 장) · 국적 · 나이 · 약속 · 영상 5개 · 퀴즈 8점. 빠진 항목을 한국어로 알려 준다(예: "성북구 주소 증빙, 교육 영상 4/5").
- 매칭: 기숙사 숙박에 같은 대학 버디 우선(AI-01·03)은 그대로. 다른 대학 거주 버디도 추천되지만 같은 학교 가산점은 없다(`university_id` 없음). 버디 상세 배지 "성북구 거주 확인".
- A03 대기 표: '자격 경로'(대학 메일 인증 / 성북구 거주 + 서류 썸네일 두 장 — `/media/`가 아니면 자리 표시 타일), '교육 영상 n/5', 거주 경로는 '서류 확인 · 승인'.
