# AI-01 일정 결과: 버디 직접 고르기 · 언어 이름 · 체크인 뒤 동행 시간

## T12 일정 결과 (`(tourist)/plan/result`)
- 버디 줄 아래 **다른 버디 고르기** → 같은 화면에 작은 목록을 펼친다. AI-03 `POST /ai/buddy-match`에 그 버디 항목의 날짜, 일정을 만들 때 고른 언어·관심사(`sessionStorage sbstay.planInput`, T11이 저장), 일정 숙소의 대학(`GET /dorms/{id}`)을 넘겨 3명까지 받는다. 줄마다 이름 · 학교·전공 · 평점 · 추천 이유 한 줄 · 가격. 지금 버디는 '지금', AI가 처음 고른 버디는 'AI 추천' 표시(후보에 없어도 맨 위에 둔다 → 되돌리기 가능).
- 고르면 일정의 그 버디 항목만 바꾼다: `ref_id`, 제목·meta의 이름과 언어, 가격(시간당 × 시간). 코스·날짜·시간은 그대로, 합계는 바뀐 가격만큼. 고른 값은 `sessionStorage sbstay.planBuddy`(plan_id가 같은 일정에만, 새 일정을 만들면 지움).
- 'AI가 고른 이유' 글은 그대로 두고, 바꿨으면 아래에 "직접 고른 버디예요 · AI 추천: 지우".
- **버디 목록에서 더 보기** → T09 `/buddies?stay=&from=&to=&course=&date=`. T09가 `?date=`(숙박 기간 안일 때)를 처음 날짜로 쓴다. 거기서 고르면 장바구니 흐름 그대로(일정으로 돌아오지 않음).
- 장바구니에 모두 담기: 고른 버디로 담는다. 버디가 있으면 코스는 버디 항목에만 붙어 있어서, 코스 제목은 `GET /tours/{course_id}`로 채운다.

## AI-01 (`services/planner.py`)
- 버디 meta 언어: `ko/en/ja` → "한국어·영어·일본어" / "Korean·English·Japanese" (`matcher.LANGUAGE`).
- 시간: 체크인 15:00. 버디 14:00, **체크인 날이면 16:00**. 버디 없이 코스만 걷는 날 10:00, **숙소가 있고 체크인 날이면 16:00**. 가격·합계 그대로.
- 테스트(`tests/test_ai_plan.py`): 언어 이름(en·ko), 1박 일정 버디 16:00·체크인 → 버디 순서·합계, 버디 없는 1박 코스 16:00 / 3박 코스 10:00.

## 목업 (`lib/mock/index.ts`)
- `/ai/plan`: 같은 시간 규칙(1박이면 도착일, 16:00), 버디가 있으면 따로 코스 줄을 넣지 않음, meta 언어 이름. `/ai/buddy-match`는 그대로 써서 바꾸기 화면이 목업에서도 동작한다.
